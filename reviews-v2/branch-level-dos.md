# Second-pass review: Branch-level Durable Objects for monorepos

# Review v2: branch-level-dos (idea #16)

## Scores
- Feasibility 4/5 (was 4). Every host call exists in `worker` 0.8.5 per the memo: `Bucket::put(key, impl Into<Data>)`, `Bucket::get(key).execute() -> Option<Object>`, `ObjectBody::bytes()` (rust-server rows 24-25); `Request::new_with_init`/`RequestInit::with_method`/`headers_mut` are present-in-source, not run (info-refs-endpoint line 12); `SqlCursor::to_array` verified (memo row 16). The multi-key-delete caveat is stale: `delete_multiple` exists (`r2/mod.rs:91`, two-phase-push review). The real gap is not an API: nothing on the read paths hands `repo_id` to the edge, so `adv_key`/`Bucket` cannot be constructed for `ls_refs_edge`/`advertise_v0_edge` (deviation 1).
- Reliability 3/5 (was 3). Served bytes are crash-clean — a torn snapshot is structurally unserveable and every failure mode degrades to the foundation path. Two failure modes are worse than the proof admits: a kill inside the `put_bytes` await strands the job `running` forever (section 4 has no running-reaper; dedup then blocks every heal — the identical hole the replicated-refs-edge review filed), and a repo whose build cannot finish in one slice retries forever because `adv_pointer` re-enqueues on `built_at=0` (line 54) and `dead` rows do not dedup (4.5); each attempt is a multi-second DO-blocking span.
- Correctness 3/5 (was 2). The accounting is honest: Mechanism and Known limits say plainly that per-branch write authority is contract-impossible (8.1, A9, section 12; CAS/`gc_epoch`/connectivity atomicity cannot cross an async stub boundary, platform-facts #4). But the artifact is not the idea — zero branch-level DOs ship. What ships is a strongly-consistent ref-snapshot cache closer to sibling replicated-refs-edge (#13) than to #16, its one real differentiator being exact-version freshness that makes it safe for the receive-pack advertisement the KV sibling excluded. The remnant itself is correct: snapshot bytes are exactly one `refs_version` and all first-pass blockers close.
- Effort: days. Three small files, all helpers exist as sibling write-backs; needs the `repo_id` plumbing, the `rearm` declaration, and a sticky cap before it can be wired in.

## Contract compliance
Matches: REGISTRY block per A9 (route `POST /_do/adv`, `JobKind::AdvBuild`, `adv` table, `r/<repo_id>/adv/` R2 prefix, lines 24-30); `jobs::enqueue` only, no `set_alarm` (4.1); dedup-by-kind used correctly (4.5); the 5.3 mark-then-delete shape — `KEEP_MS` 600 s > `max_ms` 240 s, monotonic key names, per-row DELETEs re-guarded by `built_at < cutoff` (line 106), deletion not load-bearing; rows as JSON with hex ids (1.3); `wire` formatting sync and `worker`-free (1.1); `changes()`-only write oracle, no `rows_written`; the publish re-check after the R2 await honours section 9; no `ctx.id.name` (8.3); A6 bound parameters ≤ 2 per statement; write-backs disclosed (`put_bytes`/`get_bytes`, DTO in `wire::http`, second `enqueue` in commit step 7, `run_slice` arm, line 195).
Deviations (each also in the structured list):
1. The edge cannot build `adv_key` on the read paths. `repo_id` is boot-generated random hex (8.2) returned only by `/_do/push/begin`; `Ptr{v,ready}` (line 55) and `RefsDto{head,refs}` (info-refs-endpoint lines 64-65) carry no `repo_id`, so no caller can supply the `bucket: &Bucket` that `adv_rows`, `ls_refs_edge` and `advertise_v0_edge` require (lines 118, 137, 149). A wrong-guess `repo` fails silently to the fallback. Sibling replicated-refs-edge chose name-derived `refs/<owner>/<repo>` for exactly this reason (its line 64: "the edge must compute it before any DO contact"); r2-versioned-snapshots uses `snap/<owner>/<repo>` the same way. Mechanical fix: `Ptr` gains `repo`, or the prefix becomes name-derived. Until then the snapshot path is unreachable and every listing pays the foundation fallback plus one extra stub call.
2. `/_do/adv` is registered "(awaits: none)" (line 25) but calls `jobs::enqueue` (line 54); A3 requires every route that enqueued to run `jobs::rearm(&self).await` after its span — the server-side-merge precedent declares "awaits: `jobs::rearm` only". The assumed post-span rearm ("`rearm` rides the same post-span call", line 195) does not exist: repo-do-ref-authority's `fetch` ends at `crate::edge::respond(out)` with no `rearm` (its lines 45-60) — already filed as hooks-as-workers deviation 6 and presigned-direct-upload deviation 3. Effect: an `AdvBuild` queued by a bare listing fires only at the next armed alarm, up to 15 min late on the Janitor's period.
3. "Each SELECT its own sync span" (lines 39, 62) is false: the loop body (lines 70-88) contains no await, so the whole build — up to ~120 `SELECT`s and 64 MiB of JSON — is one sync span. The in-loop drift check (line 72) is unreachable dead code; the post-`put` re-check (line 94) is the only real one. A large-repo build is a single DO-blocking span of up to ~16 s (80% of the 20 s slice budget, 4.3/A4) — the exact serialization this module exists to remove, amortized per `refs_version` instead of per listing. Compare replicated-refs-edge line 73, which honestly reads the whole table in one `SELECT`.
4. `spent_80pct()` returns `Err(Error::Budget)` (line 71) where A4 prescribes `Continue { cursor }`. Consequence: each exhausted build burns an attempt (4.4), goes `dead` after 8, and is then re-enqueued by `boot` (A4 covers "any per-repo maintenance kind") and by every `adv_pointer` call (`b==0`, and `dead` does not dedup, 4.5). A repo that cannot build in one slice retries forever, each retry a DO-blocking span triggered by ordinary reads. Known limits' "the repo permanently falls back" (line 192) is wrong: it permanently retries.
5. `built_at=-1` (over `SNAP_MAX`) is per-version (lines 28, 84): an over-cap repo re-runs the full serialization loop — up to ~64 MiB of buffer inside the blocking span — on every `refs_version` bump before rediscovering the cap. A `meta` flag making capped sticky is one row.
6. Slice-budget plumbing drift: siblings converge on a `SliceBudget.req: ReqBudget` field (bundle-uri and signed-reflog write-backs); this module hand-rolls a local `ReqBudget` (line 91) and writes `subrequests_used` back only on the success path (line 109) — a third convention, though contract-conformant.
7. `bucket.delete(&stale…)` is one call for the whole stale set (line 104); `Bucket::delete` is ≤ 1,000 keys per call (1.2). Pathological churn — ≥ 1,000 superseded versions inside `KEEP_MS`, reachable at ~2 commits/s for 10 min — makes the delete fail and the slice retry. Mechanical: chunk it.
8. `Row{name,target,peeled}` (line 60) duplicates `RefDto`, which A8 and the sibling proofs place in `wire::http`; the write-back (line 195) even says so. Mechanical rename.
9. `schema_version 4` (line 27) collides with hooks-as-workers' claim of 4 — cross-proof numbering only, trivial.

## First-pass blockers
1. Prefix-to-shard routing returned zero refs for `refs/heads/`: **resolved**. There are no shards to miss; `ref-prefix` is a `retain`/`starts_with` over the whole snapshot (line 141).
2. `register` after `updateRefs` silently omitted a new namespace on crash: **resolved**. No registry exists; the listing is `refs` captured under one `refs_version`.
3. `Promise.all` on shard RPC hid successful ref moves behind one shard's failure: **resolved by dependency**. One `commit_push` span produces per-ref results in client order (3 step 4); there is no fan-out.
4. `head()` then CAS not atomic against GC deleting `objects/<sha>` (concurrency walk-through): **resolved by contract**. No loose-object keys exist (2.2); tip liveness is `Index::lookup` inside the commit span and `gc_epoch` guards the lookup-commit gap (3 step 2, section 5).
Caveats from the first pass: missing `HEAD`/`symref-target:`/`peeled:` in ls-refs → **resolved** (`head` rides the snapshot from `meta.head`; `write_ls_refs` emits all three, A5). `command=ls-refs` unchecked → **resolved by dependency** (`parse_v2_command` -> `V2Command`, 1.1; `fetch` still runs `RepoDo::fetch_v2`). receive-pack advertisement not shown, `atomic` risk → **resolved** (`advertise_v0_edge` through `write_advertisement_v0`; caps fixed by rule 5). Every push awaits a root DO + full advertisement → **resolved** (no root DO; pushes are the unchanged foundation path; the advertisement is one O(1) span plus an edge R2 read). Hot-ref ceiling unchanged → **not resolved, honestly admitted** (8.1, section 12; CAS serialization is the contract's chosen consistency unit). Whole-shard `ng` / cross-shard `atomic` → **resolved by contract** (per-ref CAS; `atomic` never advertised). No consistent cross-shard snapshot → **resolved and inverted** (the snapshot is exactly one `refs_version`, re-checked in the publish span before `built_at` is set). Stray `ref-prefix` mints billable DOs → **resolved** (no per-prefix DOs can exist; a stray prefix is a `retain` pass).

## Crash walk-through
Kill inside the build loop: it is one sync span, so the `adv(v,0)` insert and dispatch's `running` mark roll back together; the job row stays `queued` but the alarm that fired is already consumed, so it waits for the next armed alarm (≤ 15 min on the Janitor's chain) or the next post-span `rearm` — which no route currently performs (deviation 2). Nothing durable, nothing served, `buf` was in-memory. Kill inside the `put_bytes` await: pre-await writes have committed — job `running`, `adv(v,0)` row, and possibly the `adv/v.json` object. Nothing in section 4 returns a `running` row to `queued` (4.2 selects `queued` only; 4.4 fires on a returned `Err`; A4 re-enqueues `dead` only), and dedup (4.5) then blocks every later `enqueue(AdvBuild)` — from commit step 7 and from `adv_pointer` — so snapshot builds stop permanently and listings fall back forever; the orphan key is never swept because no build ever publishes again. Identical stranded-row hole to the replicated-refs-edge review; same fix (fail `running` rows older than `PUSH_TIMEOUT`). Kill inside the publish span: uncommitted — `built_at` stays 0, same stranded outcome. Kill during the `bucket.delete` await: the publish is durable, the served path unaffected; partially deleted stale keys are re-listed by the next publish, and a `get` racing a deleted key falls through to `/_do/refs` (line 123). Clean.

## Concurrency walk-through
Pushes A and B racing a build of version v: commits cannot interleave inside the build — it is one sync span (deviation 3) — so they queue behind it, which for a 600k-ref repo is up to ~16 s of head-of-line blocking the module was designed to eliminate. During the `put_bytes` await the input gate opens: `commit_push` runs to completion in its own span, bumps `refs_version` to v+1 and enqueues `AdvBuild`, deduped against the `running` row (4.5). The publish re-check sees v+1 ≠ v and returns `Reschedule(+REBUILD_MS)`; the next slice builds v+1 and skips v — the dedup-based firehose policy works as claimed. A listing arriving mid-build runs `adv_pointer` between slice awaits, sees `built_at=0` or no row, enqueues (deduped, no-op) and returns `ready:false` -> `/_do/refs`; correct, costing one extra stub call. A commit between the pointer response and the R2 `get` serves an old-but-consistent v — the ordinary advertisement race every git server has. The sweep's DELETEs are re-guarded by `built_at < cutoff` (line 106), though under kind-dedup no second build can exist to race them.

## Interop check
All client-visible bytes come from the same `wire` writers the DO path uses (`write_advertisement_v0`, `write_ls_refs`), so `symref-target:`, `peeled:`, `unborn`, the `# service` prelude and the rule-5 capability list are identical by construction — spike-tested against git 2.43 (corrections 5). `ref-prefix` maps to byte-prefix `starts_with` over the whole snapshot, so `git clone`'s `refs/heads/` and `refs/tags/` prefixes match (first-pass blocker 1 stays closed). The decisive interop property: `ready` requires the snapshot to be for the *current* `refs_version`, so serving it for the receive-pack advertisement is CAS-safe — the advertised old-oid is never older than the pointer span — which is precisely the thing replicated-refs-edge refused to do with a stale-able KV value (its line 137). A commit between pointer and `get` is stock git's advertisement race; CAS and `not our ref` cover it. Not shown: the response glue (content-type, `NO_CACHE`, `x-ge-subrequests` accounting header) and where in `route`/`upload_pack` the new functions slot in — assumed, not demonstrated.

## Blockers
- The fast path is unreachable: no read-path route returns `repo_id`, so `ls_refs_edge`/`advertise_v0_edge` callers cannot construct the `Bucket`/`adv_key` the code requires (deviation 1). One JSON field on `/_do/adv` or a name-derived prefix fixes it; without it the module is dead code that costs an extra stub call per listing.
- `/_do/adv` must be declared "awaits: rearm" and the `fetch` wrapper must actually rearm — the latter exists in no sibling `fetch` (deviation 2; same gap filed against hooks-as-workers and presigned-direct-upload).
- Unbuildable repos retry forever instead of falling back (deviations 4-5): `spent_80pct` exhaustion needs a real `Continue` cursor per A4, or a `meta` flag must make cap/budget failure sticky — otherwise every read on exactly the oversized monorepos this module targets triggers a ~16 s DO-blocking span, strictly worse than the foundation.

## Caveats
- The narrowing is honest and disclosed — but what remains is closer to sibling #13 (replicated-refs-edge) than to the named idea: an R2-backed, exact-version snapshot publisher covering the receive-pack advertisement the KV variant excluded. If both land, two near-identical snapshot pipelines exist; a portfolio question, not a defect.
- Stranded `running` rows (a section-4 gap with no reaper) kill this module permanently on one unlucky isolate kill; the stale-`running` reset the sibling reviews already requested belongs here too.
- `KEEP_MS` guards deletion by `built_at` age, not time-since-superseded; the real safety margin is that the pointer→`get` gap is microseconds inside one request, which holds — the "2 × `max_ms`" reasoning (line 41) is loose, but the fallback makes any loss benign.
- Under a true write firehose every listing still pays `/_do/refs` plus the `/_do/adv` stub call — net +1 subrequest over the foundation, and the snapshot is never current; stated honestly (line 191).
- Unverified at runtime, shared class: the `Request::new_with_init` stub path, R2 `put`/`get` consistency on real R2 (platform-facts #6 covers multipart only, on the simulator), `web_sys::Crypto` for `repo_id`, the production subrequest limit.
- `Bucket::delete_multiple` exists (`r2/mod.rs:91`); the single-key fallback worry (line 13) is unnecessary.
- `Depends on: gc-and-repack-alarm` names a proof with no second pass; the machinery is contract section 5 now — cosmetic.
- `Row` should be the shared `RefDto` in `wire::http` (deviation 8); `schema_version` numbering collides with hooks-as-workers (deviation 9).

## Verdict
lands-with-caveats. The idea as named does not land and the proof says so itself — per-branch DOs are contract-impossible, and the disclosed remnant is a correct, well-reasoned reader-isolation module whose consistency story is stronger than the first pass's sharded fan-out ever was. All three first-pass blockers close structurally and the crash walk is clean for everything served. What keeps it out of a clean `lands` is wiring, not design: the edge cannot learn `repo_id` on a read path so the snapshot path cannot be invoked, the enqueue's rearm does not exist in the sibling dispatcher, and an unbuildable repo retries DO-blocking spans forever instead of falling back. All three fixes are mechanical; the deeper question the brief poses — honest accounting versus a different idea wearing the same name — resolves to both: it is honest accounting for a remnant that honestly belongs to idea #13's family.
