# Second-pass review: Live fetch over hibernating WebSockets

# Review v2: live-fetch-websocket (idea #15)

## Scores
- Feasibility 4/5 (was 4). Every host call exists in `worker` 0.8.5 on docs.rs, signatures exact: `State::{accept_websocket_with_tags(&WebSocket, &[&str]), get_websockets, get_websockets_with_tag(&str), set_websocket_auto_response(&pair)}`, `WebSocketPair { pub client, server }` with `new() -> Result<Self>`, `WebSocketRequestResponsePair::new(&str,&str) -> Result<_,JsValue>`, `Response::from_websocket(WebSocket)`, `WebSocket::{send_with_str, send_with_bytes, close(Option<u16>, Option<S>), serialize_attachment, deserialize_attachment -> Result<Option<T>>}`, `durable::WebSocketIncomingMessage::{String(String), Binary(Vec<u8>)}`, and the three `websocket_*` trait hooks match the commented code arg-for-arg (`usize`, `String`, `bool`; `worker::Error`). `bufferedAmount` is indeed absent. What is not proven is behaviour, not API: hibernation, the output gate on ws sends, the 101 pass-through, and every platform cap — none touched by the spike or platform-facts. As written the file does not compile against its siblings (mechanical, below).
- Reliability 4/5 (was 3). The first pass's lost-nudge window is gone by construction: fanout sits inside the commit span with no await, so only an output gate can separate the ref move from the nudge, and `{"t":"tips"}` re-derives missed moves at reconnect. A wedged fetch clears itself after `BUSY_STALE_MS` = 5 min; session and attachment rot are bounded by `exp` + `LiveSweep`. Residuals: the catch-up only covers refs the client already knows, the output-gate claim for sends inside a span is unmeasured, and `LiveSweep` scans every socket in one span with no budget check.
- Correctness 4/5 (was 2). The in-socket reply is now the section-9 pipeline verbatim — `parse_v2_command`, `Index::lookup` for wants and haves, 9.2 readiness, `write_fetch_prelude`, `send_set_shallow`, `write_pack` — so the `done`-omission that killed `fetch-pack` in pass one is the sibling's fixed code, not a re-implementation. Deductions: the code does not compile as written (`Sideband::new`, `CmdDto` visibility, `now_ms` import), the edge route makes an uncharged stub call against 7.1, added scenario 20 pipes sideband-framed bytes into `index-pack --stdin`, which cannot parse them, and a ref created while the client was disconnected is never announced.
- Effort: weeks. The module itself is days; it needs the whole fetch path (partial-clone-filters' `send_set_shallow`/`write_pack`), and the ws helper client is unbuilt software on the far side of this proof.

## Contract compliance
Matches: A9 REGISTRY block listing all write-backs (a)-(f); no tables, no R2 key prefixes, one `JobKind::LiveSweep` added through section 4's extension point; `enqueue` inside the upgrade span with `rearm(self).await` after it (A3); `json_each(?)` for the tips IN-list (A6); budget-carrying calls into `send_set_shallow(.., &mut budget)` and `write_pack(.., budget)` (A1); readiness `args.done || args.haves.is_empty() || !acks.is_empty()` is 9.2 verbatim; unknown want answers the section-10 `ERR upload-pack: not our ref` line; unknown haves dropped (9.1); errors inside DO spans surface as `{"t":"err"}` frames rather than HTTP codes, the socket-path analogue of the after-bytes rule; client bytes validated (`name_partial`, `ObjectId::from_hex`, `serde_json`) with no unwrap/indexing (section 10); WebSockets correctly treated as post-foundation (section 12).
Deviations (each also in the structured list):
1. `live_route`'s `stub.fetch_with_request(req).await` (line 75) is uncharged: 7.1 rule 1 says every stub call goes through `budget.charge(1)` and no `ReqBudget` is ever created on this route. One subrequest; mechanical.
2. `Sideband::new(&mut w)` (line 201) does not exist: `wire::Sideband` keeps `w` private and protocol-v2-only defines only `data`/`error`/`progress` — there is no constructor to call from outside `wire`, and the REGISTRY does not list adding one. Mechanical but compile-blocking.
3. `live_fanout` reads `cmd.name`/`old`/`new` (lines 115-119) and `res.results` — `CmdDto` and its fields are private in repo-do-ref-authority (`struct CmdDto { old: String, .. }`, no `pub`); write-back (f) grants `pub(crate)` to the `RepoDo` helpers but not to `CmdDto`. Compile-blocking, mechanical.
4. `now_ms()` is called unqualified (lines 104, 106, 209, 212, 233) but is absent from the `use` block (lines 40-44); the sibling defines it privately in `repo_do`. One-line import, mechanical.
5. `write_fetch_prelude` is called with five arguments including `unshallow` (lines 191, 200); protocol-v2-only defines `(w, args, acks, shallow) -> Result<bool, Error>`. Registered as write-back (d), so declared, but it edits a function another sibling owns and both call sites discard the bool that decides whether a pack follows — here harmless because readiness was pre-checked, but the signature is now load-bearing in two proofs.
6. `run_live_sweep` takes `_b: &mut SliceBudget` and never checks `spent_80pct()` (A4): one sync span scans `get_websockets()` and deserializes every attachment, unbounded by the platform's socket cap.
7. The `/live` arm ends `return wire::http::respond(out)` (line 83 comment) — the same shape the sibling review flagged as a blocker: if `respond` converts a mid-span `Storage`/`Internal` `Err` into a `Response`, A2's throw-for-rollback is bypassed. Benign here (the only span writes are the `jobs` row and the attachment) but it repeats a pattern already judged wrong.
8. Scenario 20 (line 284) feeds concatenated binary frames to `git index-pack --stdin`: the reply is pkt-line/sideband framed, which `index-pack` cannot parse; the step needs `git fetch-pack --stateless-rpc` or a demux before `index-pack`. The first-pkt-is-`packfile` assertion is still the right regression check.
9. `live_tips` (lines 126-151) diffs only the names the client claims: a ref created while the client was disconnected, in a name it never knew, produces no diff and no nudge. The `*` subscription does not fix this because tips, not tags, drive the catch-up.
10. While the DO is awake, a literal `"ping"` text frame reaches `live_tips`, fails `t != "tips"`, and gets `{"t":"err"}` instead of `pong` (line 211); the auto-response only answers while hibernated. Cosmetic.

## First-pass blockers
1. "Reconnect seeds `have` from server tips instead of client-reported tips; must accept client tips and nudge on mismatch": **resolved**. `Attach` carries no tips at all; the client claims its tips in `{"t":"tips"}` and `live_tips` diffs claim vs `refs` in one sync span, nudging every mismatch including deletions (`new: null`). The server can no longer believe the client is current when it is not. Residual hole is deviation 9 — moves on refs the client never knew are still missed.
2. "v2 response framing wrong for `done` requests -> real fetch-pack dies": **resolved by dependency**. The reply is emitted by the sibling's `write_fetch_prelude`, which writes `acknowledgments` only under `if !args.done` (protocol-v2-only lines 150-161) — the identical fix its own first pass demanded. Verified in that proof's code, not just cited.
3. "Attachment growth breaks the 2 KiB `serializeAttachment` cap": **resolved**. `Attach { exp, busy_ms }` is two i64s, ~40 bytes of JSON, constant-size; haves travel as `have` lines inside each fetch body and nothing accumulates.
4. Crash-walk, "DO evicted between commit and send loop; reconnect seeds tips = client stuck": **resolved**, both halves. `live_fanout` runs inside the commit span (`.map` on `commit_push`'s result, no await between CAS and sends), so the window is the output gate, not an eviction; and reconnect no longer seeds anything server-side.
Caveats from the first pass: ">10 refs as tags" -> `*` tag plus a two-query fanout, a socket holds one kind or the other so no double-send: **resolved**. "No send backpressure" -> `LIVE_BYTES_MAX` checked from exact `set.reads.ents` lengths before `write_pack`, one reply in flight, ~8.2 MiB buffered per socket: **resolved** (the cap is the flow control; `bufferedAmount` confirmed absent). "Deploys drop sockets; reconnect with tip comparison" -> **resolved** via the same tips mechanism, subject to deviation 9. "Auth expiry via alarm unimplemented; constructor exec in blockConcurrencyWhile" -> `LiveSweep` + lazy `exp` check, and there is no constructor exec to move (schema lives in `boot`): **resolved**. "Busy repos never hibernate" -> **not resolved**, restated honestly as a platform fact. "Server sends pkt strings as text frames" -> all protocol bytes go through `send_with_bytes`: **resolved**.

## Crash walk-through
Kill inside the `live_upgrade` span: pair created, `accept_websocket_with_tags`, attachment, `jobs::enqueue` — all one span. A throw rolls back the job row; the client never saw a 101 so its socket dies. If `respond` instead converts the error (deviation 7), the `LiveSweep` row commits while the client is refused — a queued sweep with zero sockets ends `Done` on first firing; harmless either way. Kill inside the commit span mid-fanout: if the output-gate claim holds, sends and ref writes roll back together; subscribers miss the move and heal through `tips` for known refs. Kill during `live_fetch_bytes`'s awaits (`send_set_shallow`/`write_pack`): the module has written nothing durable except `busy_ms`, which was serialized before the first await; the next frame inside 5 min gets `one fetch at a time`, after 5 min the mark is treated as handler death and the fetch proceeds. Nothing partial reaches the wire because all sends are post-generation in one span — a kill lands either before the span (no bytes) or after (all bytes through the gate). Kill inside `LiveSweep`'s scan: one span, nothing persists, next firing rescans; a `dead` LiveSweep row is re-enqueued at the next `boot` under A4's maintenance-kind rule or by the next `live_upgrade` anyway. Kill while hibernated: no isolate exists; sockets, tags and attachments are runtime-owned and survive; the next message wakes the DO and re-boots.

## Concurrency walk-through
The input gate opens at every `live_fetch_bytes` await (measured #4 on R2 awaits). A `commit_push` span arriving mid-fetch runs to completion — sync spans cannot interleave — and its nudge text frame lands between the fetch's binary messages; the helper splits on frame type, so pack bytes are never corrupted. A second binary fetch frame on the same socket deserializes the attachment after the first fetch's pre-await `serialize_attachment`, sees `busy_ms`, and is refused — the check-then-set sequence is one span, so the race cannot produce two replies. A `tips` frame mid-fetch reads `refs` in a sync span: consistent. A `GcSweep` span between the fetch's `Index::lookup` and a later `plan_reads`/`pack_chunk` can yield `Error::Internal` on a deleted `objects` row — an err frame where the pack's R2 bytes would still have read fine for another GRACE; same exposure `/_do/fetch` already has, not a new hole. `live_upgrade` racing a commit: disjoint spans — a socket accepted before the commit's span runs is tagged and nudged; one accepted after was never owed the nudge and catches up on `tips`. `LiveSweep` closing a socket concurrently with `live_fanout` sending to it: `send` failure is swallowed by contract (best-effort nudges).

## Interop check
Stock `git` sees nothing — no WebSocket transport exists and none is claimed; the stock-compatible mode is nudge -> HTTP `git fetch`, unchanged. The helper sees: text frames = JSON control (`ref`, `err`, `http`, and its own `tips` upstream), binary frames = the exact byte stream `/_do/fetch` produces. After `done` the first section is `packfile` (or `shallow-info`), which is what killed `fetch-pack` in pass one and is now right by reuse. The `ERR upload-pack: not our ref <oid>` pkt-line for a fabricated want is what a stateless-RPC client expects. Byte details: the response ends with `w.flush()` (line 202), satisfying rule 3; sideband data frames are capped at 65515 by `Sideband::data` (rule 2, contract-owned); the 64 KiB `send_with_bytes` chunking crosses pkt-line boundaries freely, which is legal only because the helper must concatenate the binary stream before parsing — a client that parsed per WebSocket message would break, and the proof states the convention but the added scenario never asserts it. `?refs=` names go through `name_partial`, which accepts bare `main` where git wants `refs/...` — harmless for tagging, same laxity the sibling review noted.

## Blockers
- The code does not compile against its siblings as written: `Sideband::new` does not exist (private field, no constructor, unregistered), `CmdDto`'s fields are private to `repo_do`, and `now_ms` is not imported. All three are one-line fixes, but the crate does not build until they land — same class as the foundation-pass signature drift.
- Scenario 20's harness step is wrong as written: `index-pack --stdin` cannot consume pkt-line/sideband bytes; the proof's own blocker-2 regression assertion needs `fetch-pack --stateless-rpc` or an explicit demux.

## Caveats
- Reconnect catch-up covers only refs the client already knows (deviation 9): a ref created while disconnected is never announced; the client contract needs a periodic `ls-refs`-equivalent (over HTTP) or a tips-diff against the subscribed set server-side.
- The load-bearing platform claims are all unmeasured: output-gate release of ws sends and `serialize_attachment` on span commit, 101 pass-through on `fetch_with_request`, hibernation wake on `websocket_message`, and the 10-tag / 2 KiB / 1 MiB / socket-count caps — none appear in platform-facts or the spike.
- `run_live_sweep` ignores `SliceBudget` (A4); at the platform's socket cap the scan is one unbounded sync span.
- `live_route` skips `ReqBudget` (7.1); one uncharged subrequest per upgrade.
- `write_fetch_prelude`'s new `unshallow` parameter (write-back d) changes a signature owned by protocol-v2-only; the sibling must adopt it, and both proofs now depend on the same edit landing.
- Awake-DO `ping` gets `{"t":"err"}` not `pong` (deviation 10); helpers should rely on the hibernated-path auto-response only.
- `RepoHeaders::NONE` is assumed in `wire::http` per A8 while the sibling still writes `crate::edge::RepoHeaders`; wherever it lands, this module needs it.
- Busy repos never hibernate (restated); the zero-duty-cycle cost story applies to quiet repos only, and fanout is N synchronous sends inside the commit span.

## Verdict
lands-with-caveats. A real rewrite, not a patch: all three first-pass blockers and the crash-window finding are closed structurally — client-claimed tips instead of server-seeded state, the sibling's fixed prelude instead of hand-rolled framing, a constant-size attachment, and the fanout moved inside the commit span so only the output gate stands between a ref move and its nudge. Reliability 3->4, correctness 2->4. What remains is mechanical compile drift (`Sideband::new`, `CmdDto` visibility, `now_ms`), one wrong harness step, an unbounded sweep scan, and a genuine residual: refs born while the client was away are still invisible until something else moves them.
