# Second-pass review: Diff API served with R2 range reads

# Review v2: diff-api-range-reads (idea #27)

## Scores
- Feasibility 4/5 (was 4). Every host call exists: `SqlStorage::exec`/`SqlCursor::to_array`, `Index::lookup` (2.3, live-only join), `Bucket::read_entries` (A1 shape, charges per coalesced span inside `read_range`), `codec::decode_entry`, `Response::from_stream` (`S::Ok: Into<Vec<u8>>, S::Error: Into<worker::Error>`). But the pinned-name story is worse than the proof's "one-line fix": verified against docs.rs, every `imara_diff` call in `unified()` is the 0.1.x API — 0.2.0 has no free `diff()` and no `UnifiedDiffBuilder`; the shape is `Diff::compute(Algorithm::Histogram, &input)` then `diff.unified_diff(&BasicLineDiffPrinter(&input.interner), UnifiedDiffConfig::default(), &input).to_string()` (`unified_diff` is a default feature). Three gix-object `from_bytes` calls miss the second `object_hash` arg; `TagRef.target` is `&BStr`, not `ObjectId` (`.target()` is the method); `EntryMode::bits()` is `value()`; `EntryRef.oid` is `&oid`. All mechanical, none architectural, but the file does not compile as written.
- Reliability 4/5 (was 3). Read-only: nothing is written, so no sync span needs atomicity (A2 rollback moot). Every race resolves through the live-only 2.3 query into a 404, an `"omitted":"swept"` record, or one `{"error"}` record — never a deref. Caps bound a request to roughly 32 MiB trees + 32 MiB batch + ~33 MiB of emitted patch text + ~2.4 MiB of pairs, under 128 MB. Residual: a maximally scattered diff hits `Error::Budget` mid-stream at ~4,500 pairs (deviation 6) and the whole tree walk runs before the first record, so first-byte latency on a large diff carries every tree read.
- Correctness 3/5 (was 2). Both first-pass blockers are dead by construction and the descent is honest — Mechanism and Known limits say plainly that "diff without reconstructing files" is the part the contract removes. What remains is a real diff: histogram over fully reconstructed sides, mode-only/identical/add/delete/binary as first-class record shapes. Deductions: `diff_trees` silently drops the deletion record when a blob becomes a tree (deviation 1 — wrong output for a common case, not a nit); the `patch` field as emitted is bare `@@` hunks that `git apply` cannot consume, so scenario 18's oracle cannot run as written; and the idea's differentiator ("no reconstruction") is gone — what lands is a conventional diff server with an efficient read path.
- Effort: weeks. The route, walk and streaming shell are done-shape; the fixes are local. Dependencies are all v2 siblings.

## Contract compliance
Matches: A9 REGISTRY block (lines 23-27) lists both routes and the `DiffIn` DTO, no `JobKind`, no table, no R2 prefix; awaits class of `/_do/diff` matches `/_do/fetch` (1.3, write-back proposed); all object resolution through `Index::lookup` + `read_entries` with the A1 budget arg; 16 MiB object cap inherited from A7 and charged through `loc.size`; pre-stream errors through `respond` to section-10 statuses; mid-stream error is one record, the 9.6 band-3 analogue; `budget.charge(1)` before the stub call (7.1); no `set_alarm` (4.1); exactly two added scenarios (section 11); scenario set 2, 3, 4, 12, 14 is right for a read-only route.
Deviations (each also in the structured list):
1. `diff_trees` drops blob->tree deletions (lines 241-245): for `!o.tree && e.tree` the `else` binds to `if e.tree`, so the add-frontier is pushed and no `Pair { old: Some(_), new: None }` is emitted for `path`. A file replaced by a directory produces only the added files under `path/`; the deletion of `path` itself is lost, and a client folding records onto `from` keeps a file git deleted. One-line fix, but it is a correctness hole.
2. `unified()` (lines 225-230) does not compile against imara-diff 0.2.0: `imara_diff::diff` and `UnifiedDiffBuilder`/`finish` do not exist. Required: `Diff::compute(Algorithm::Histogram, &input)`, optional `postprocess_lines(&input)` (the slider heuristic `git diff` applies), then `unified_diff(&BasicLineDiffPrinter(&input.interner), UnifiedDiffConfig::default(), &input).to_string()`. `InternedInput::new(a, b)` on `&[u8]` is fine (`TokenSource for &[u8]` = byte-lines; `new(before, after)` gives the right old->new direction). ~5-line rewrite — mechanical, but larger than the claimed one-liner.
3. gix-object 0.64.1 drift, all verified on docs.rs and shared with search-index-on-push (same calls at its lines 122/134/124): `TreeRefIter::from_bytes(d)` needs `(d, gix_hash::Kind::Sha1)` (line 260); `CommitRef::from_bytes(&d)` and `TagRef::from_bytes(&d)` likewise (lines 105-106); `TagRef.target` is the hex `&BStr` field — the `ObjectId` is `.target()` (line 106); `EntryMode::bits()` does not exist — `value() -> u16` (line 267); `Ent { oid: e.oid }` needs `e.oid.to_owned()` since `EntryRef.oid: &oid` (line 262) — the `o.oid == e.oid` comparisons do compile via `PartialEq<&oid>` on `ObjectId` (gix-hash 0.26.2).
4. `crate::wire::http::respond(self.diff(body).await)` (line 57): the sibling signature is `respond(out, pkt)` (auth-and-multitenancy line 114; `pkt=false` here) and repo-do-ref-authority still calls `crate::edge::respond(out)` — module and arity are unsettled across proofs. Also, converting `Storage`/`Internal` inside the DO is a literal deviation from A2 ("never convert it to a Response inside the DO"); harmless for a read-only route since no uncommitted span exists.
5. `x-ge-subrequests` cannot exist on this route: `Response::from_stream` flushes headers before the stream's final `budget.used` exists. The in-band trailer `subrequests` field is the only channel, so the scenario-18 header assertion (lines 297, 309, 323) cannot hold as written.
6. Budget arithmetic (line 297) counts `read_entries` calls, but the sibling implementation charges one subrequest per coalesced span inside `read_range` (refs-sqlite-objects-r2 lines 150, 170). Worst case is `ceil(pairs/32)` x 64 spans ~ 40,000 subrequests at `MAX_PAIRS`, well over `max_subrequests = 9,000` — the diff ends `{"error"}` around ~4,500 scattered pairs, not "far under" the cap. Common case coalesces to a few spans per call and the claim holds.
7. "lookup batches at 90 (A6)" (line 160 comment) misstates the sibling: `Index::lookup` in refs-sqlite-objects-r2 is a per-id `exec` loop (its lines 130-144). Harmless — <= 64 sync statements, no awaits — but the comment is wrong.
8. `Depends on: gc-and-repack-alarm` (line 329) names a proof with no v2 file; its content is CONTRACTS section 5. Bookkeeping nit.
9. `oid(arg)` first means `ObjectId::from_hex` accepts a 64-hex argument too (gix-hash 0.26.2 documents 40- and 64-hex); it resolves to a sha256 id that can never be live and 404s rather than 400. Harmless.
10. `oid(&t.target)` (line 94) maps a corrupt `refs.target` to `Error::Protocol` -> 400; server-row corruption should be `Internal` -> 500. Trivial.

## First-pass blockers
1. "No delta-storing pack exists in the foundation" (a same-path-predecessor delta encoder unbuilt): **resolved by contract**. Sections 2.1 and 12 make the absence permanent; the proof removes the fast path outright instead of building the encoder. This is the honest move — the idea's differentiator is declared dead rather than faked — and the surviving mechanism is real: coalesced range reads of exact-`len` full entries + in-isolate histogram.
2. "Delta ops are not a diff": **resolved**. No opcode stream is interpreted anywhere; hunks come from imara histogram over real contents, with binary, mode-only, add and delete as record shapes.
Caveats from the first pass: `inflateSync` over-read tolerance -> **resolved** (moot: `objects.len` is exact entry length, `gix-zlib` inflates exactly those bytes, spike-verified). Fallback path could exceed 128 MB -> **resolved** (no chains under 2.1; A7 16 MiB per side plus `TREE_CAP`/`PAIR_BATCH`/`DIFF_CAP` bound a request under 128 MB). "R2 put complete before row visible" + one-GC grace -> **resolved** (section 3 ordering + `state='live'` join + `GRACE = 1 h` at 5.3, longer than `max_ms` 240 s). `TextDecoder` mangling -> **resolved** (`binary()` gates on NUL-in-8,000 plus full UTF-8 failure; `patch` emitted only for valid UTF-8). Hand-waved commit->blob-pair walk -> **partially resolved** (implemented as `walk_all`/`diff_trees`, but see deviation 1's dropped deletion). TypeError-on-null and deleted-key races -> **resolved** (live-only lookup; misses are 404/`"swept"`, never a deref). Thin-pack deltas never persisted -> **resolved** (moot; no delta bytes are wanted). `pack_objects` rewrite atomicity -> **resolved** (moot; no such table, no repack). N+ serialized R2 GETs -> **partially resolved** (coalesced `ceil(N/32)` calls, but per-span charging means the worst case is worse than claimed — deviation 6; one-isolate serialization remains, disclosed).

## Crash walk-through
Kill the isolate at any await — peel `read_obj`, a `walk_all` span read, an `emit_batch` read — and nothing was ever written: no table row, no R2 key, no job. The `DiffSt` state dies with the request; the client sees a truncated body or a 5xx and retries identically. A kill after `Response::from_stream` returns but mid-body aborts the chunked stream; the client may see neither `{"error"}` nor the trailer — absence of the trailer is itself the failure signal, and records already delivered are valid since each is self-contained. A dead pack whose row was swept before an R2 delete (Janitor step 3 needs `dead` + GRACE) can still be range-read; a swept row is only ever a miss. Budget or `max_ms` exhaustion surfaces as `Error::Budget` inside `step` and becomes one `{"error"}` record. Nothing is orphaned at any point; cleanup is a no-op.

## Concurrency walk-through
Two diffs on one repo interleave at every R2 await inside the single DO isolate. Every `Index::lookup` is a sync per-instant live view; pack bytes under a `live` row are immutable, so no torn content is possible. A `commit_push` between two of the diff's awaits changes nothing already captured — `from`/`to` oids are resolved once up front and their objects stay live by connectivity (2.5) — so the answer is a consistent pair of snapshots taken at slightly different instants: stale-but-valid. A `GcSweep` between lookups deletes rows, yielding `"omitted":"swept"` or `{"error":"tree swept mid-request"}`; bytes persist for GRACE anyway. The input gate opens at every await and nothing behind it is mutated — the one thing a race can produce is a partial diff, never a corrupt one (deviation 1's hole is a logic bug, not a race). Aggregate throughput is one isolate wide; each request is bounded by 9,000 subrequests / 240 s.

## Interop check
No git wire protocol; `git` 2.4x is unaffected. The client is any HTTP caller with Basic auth (section 12 read token suffices). `HEAD`/`head` resolves through `meta.head` to a full ref; other names must be full `refs/...` names (`name_partial` admits `main` but the `refs` lookup then misses -> 404 — acceptable but worth a line). A 40-hex arg wins over a ref name of the same text. The `patch` field is the interop problem: imara 0.2.0's `unified_diff` emits `@@` hunks only — no `diff --git`, no `--- a/x`/`+++ b/x` headers (the crate's own doc example starts at `@@`) — so `git apply` has no filename to apply to and the emitted bytes are not self-contained. Scenario 18's "git apply of each patch" therefore cannot run as written; `record` must prepend `---`/`+++` lines (and `/dev/null` sides or `new file mode`/`deleted file mode` for adds/deletes) or the harness must synthesize them. Renames surface as delete+add; gitlinks and mode-only records are disclosed limits, not violations.

## Blockers
- `diff_trees` drops the old blob when a path changes file -> directory (lines 241-245): the `else` arm is skipped whenever `e.tree`, so no deletion record for `path` is emitted. Silently incomplete diffs on a common case; the fix is one `pairs.push`.
- `unified()` does not compile against the pinned imara-diff 0.2.0 (lines 225-230): the `diff()`/`UnifiedDiffBuilder`/`finish` names are the 0.1.x API. Rewrite to `Diff::compute` + `unified_diff` (+ `postprocess_lines` for git-like slider placement), and emit `---`/`+++` headers if `git apply` remains the oracle.
- gix-object 0.64.1 arity/type fixes (lines 105-106, 260, 262, 267): second `object_hash` arg on all three `from_bytes` calls, `.target()` instead of `.target`, `value()` instead of `bits()`, `e.oid.to_owned()` in `entries`. All mechanical; the file does not build without them.

## Caveats
- The subrequest claim is per-call while charging is per-span; worst case ~64x the stated number, still failing cleanly into `{"error"}`.
- `x-ge-subrequests` cannot be emitted on a streamed response; only the trailer's `subrequests` field is real.
- `respond` module/arity unsettled across proofs (`edge::respond(out)` vs `wire::http::respond(out, pkt)`); the stream's `S::Error = Error` also needs a `From<Error> for worker::Error` that no sibling shows — or annotate `Ok::<Vec<u8>, worker::Error>`.
- The whole tree walk precedes the first record; pairs found early are not emitted incrementally, so a large diff delivers header, silence, then records.
- The honest descope is creditable — "diffs without reconstruction" is stated as dead in Mechanism and Known limits — but it should be said plainly that the idea's edge over an ordinary diff endpoint is now only the read path.
- `main`-style short names validate under `name_partial` and then 404; sha256-length hex 404s; corrupt `refs.target` maps to 400 not 500.
- Still unverified at runtime, per the proof's own list and shared with siblings: `Url::query_pairs` re-export, `Request::new_with_init`/`RequestInit` constructor path, `futures-util` `once`/`unfold`/`chain` under `default-features = false`, `SqlStorage`/`Bucket` as `'static` stream state, real-R2 range behaviour (#6), DO subrequest enforcement (#7).

## Verdict
lands-with-caveats. The second pass converts a wrong mechanism into a real one and does the accounting honestly: both first-pass blockers die structurally (contract forbids stored deltas; hunks are computed, not decoded), the races collapse into explicit records, and the read path — live-only lookup plus coalesced exact-`len` range reads — is the thing the title promises. What remains is local: one dropped-deletion case in `diff_trees`, an imara-diff rewrite bigger than advertised, a `patch` field that is not `git apply`-able as emitted, a per-span budget bound the arithmetic understates, and a pile of mechanical API drift shared with search-index-on-push.
