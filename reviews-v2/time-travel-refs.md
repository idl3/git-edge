# Second-pass review: Time-travel refs

# Review v2: time-travel-refs (idea #20)

## Scores
- Feasibility 4/5 (was 4). Every host call exists in `worker` 0.8.5 source: `SqlStorage::exec(&str, Option<Vec<SqlStorageValue>>)` -> `SqlCursor` with `to_array`/`one` (memo section 1, spike), `js_sys::Date::now()`, all synchronous, all inside the `/_do/ls-refs` "none" span (1.3). No R2, no stub call, no `Reflect`, at most 4 bound parameters (A6). What it does need is four write-backs into foundation bodies (`ls_refs`, `apply_one`, GcMark, `boot`) plus `pub(crate)` on the sibling helpers it imports — all declared, none free.
- Reliability 4/5 (was 4). The reflog row shares the `commit_push` sync span, so it cannot diverge from the ref (section 3 step 4, platform-facts #4). Crash paths are read-only or single-statement. Residual: `ReflogExpire` re-enqueues inside its own slice while its `jobs` row is `running`, so dedup-by-kind (4.5) refuses the insert and the daily cadence silently dies after the first run — reflog growth and `gc_roots` retention then rest on `boot` re-enqueue alone (write-back d).
- Correctness 3/5 (was 4). The exact `refs/at/<t>/<name>` path is right: `at < hi` on a second-granularity epoch is git's `@{T}`, `new = zero` means deleted (line 99), and `send_set` step 1 accepts any live oid (partial-clone-filters line 60). Deductions: the "unique enumeration names" claim (line 51) is false — `r.at / 1_000` (line 77) collapses ms-distinct rows into one second, so two moves of one ref in one second emit identical names with different shas and the shared name re-resolves to the newer move; ms-epoch enumeration is silently empty (deviation 6); and "one sync statement a day" fails on the dedup bug above.
- Effort: days. The module is ~100 lines of sync SQLite; the work is the four write-backs and two mechanical fixes.

## Contract compliance
Matches: `/_do/ls-refs` stays a "none" route (1.3) — `rows`/`newest`/`gc_roots` are pure sync SQLite with no await, no R2; the reflog write stays inside the commit span (3 step 4), `at_ms` adding one sync `SELECT MAX(at)`; no `set_alarm` anywhere — `ReflogExpire` is a `JobKind` registered under A9 and `enqueue` is sync (4.1, A3); no `rows_written`; no new R2 key prefixes (2.2); `gc_epoch`/`refs_version` machinery untouched; `Error` enum untouched (10); scenarios added: exactly two (section 11).
Deviations (each also in the structured list):
1. `run_slice` here is `pub fn` (line 122); contract 1.4's `run_slice` and every sibling per-kind handler are `pub async fn`. Compiles as a sync call inside an async dispatch arm — mechanical.
2. `ReflogExpire`'s self-`enqueue` runs inside the slice (line 126) while its own `jobs` row is `running`; 4.5's dedup ("at most one `queued` or `running` row per kind") refuses the insert, so the daily recurrence dies after one run. Contract recurrence is dispatch-side (4.2's Janitor parenthetical: re-enqueue in the `Done` application) or `SliceOutcome::Reschedule{run_at}` — the shape live-fetch-websocket line 241 uses. One-line fix.
3. Four write-backs edit foundation bodies — `ls_refs` gains the `rows()` hook, `apply_one` gains `reserved()` + `at_ms`, GcMark unions `gc_roots()`, `boot` enqueues `ReflogExpire` (lines 23-27, 157). A9 registers additions (routes, `JobKind`s, tables, R2 prefixes); editing section-1/3/5 function bodies is beyond its literal scope. Declared honestly in the REGISTRY comment and Known limits; each is small.
4. `d.q`, `d.sql`, `now_ms` are asserted `pub(crate)` (line 27) but repo-do-ref-authority declares them private `fn` (its lines 72-78); siblings that assume the same visibility list it as an explicit write-back (live-fetch-websocket write-back (f), wasm-git-core). Shared, mechanical.
5. Enumeration names are second-granularity (`r.at / 1_000`, line 77) while `at` is unique only in ms (lines 52-55): two transitions of one ref inside one second emit identical names with different targets, and the shared name re-resolves through `newest` (`at < hi`, line 97) to the *newer* move — an advertised line whose sha the advertised name cannot fetch back. Emitting `r.at` (13 digits) instead of `r.at / 1_000` fixes it; the namespace already parses ms epochs (lines 106-109).
6. `refs/at/<11-13-digit>` enumeration is silently empty: emitted names are second-granularity and `write_ls_refs`'s `wanted` filter (`starts_with`, protocol-v2-only line 122) drops every synthetic row, though `handle` computed them (lines 74-80) and the proof claims "any digit prefix" enumerates (line 8).
7. The registered index `reflog_name_at(name, at, id)` serves `newest` (`name=? AND at<?`) but not the enumeration query `WHERE at>=? AND at<? ORDER BY at DESC` (line 75) — leading column `name` is unconstrained — so every bare enumeration is a full reflog scan + sort, bounded only by `LIMIT 1000`.

## First-pass blockers
1. `want-ref`/`ref-in-want` path unhandled: **resolved**. Rule 6 advertises no `ref-in-want` (1.1, section 12), `parse_fetch` rejects `want-ref` as an unknown argument (protocol-v2-only lines 105-111, `_ => Err(bad)`), and `send_set` step 1 serves any live oid (partial-clone-filters line 60), so no `wanted-refs` section is ever needed. Closed by the contract, not new code — as claimed.
2. Private `setAlarm(+24h)` would overwrite the shared DO alarm: **resolved**. `ReflogExpire` is a `JobKind` on the section-4 dispatcher; nothing in the module calls `set_alarm` (4.1, A3); second `setAlarm` cancels the first, measured (#5). The recurrence it replaced has its own new defect (blockers below).

Caveats from the first pass: monotonic `ts` clamp -> `at_ms` = `max(now_ms(), MAX(at)+1)` inside the span (lines 52-55): **resolved**. Unbounded bare enumeration -> `ENUM_MAX = 1,000` newest-first (line 36) plus digit-prefix windows: **resolved**. Expiry deletes rows, GC drops objects, advertisements dangle -> `gc_roots` unions reflog tips into GcMark (write-back c) and expiry keeps the newest row per name (line 124): **resolved**, with a documented residual race needing the >= 10-minute `GcMark` -> `GcSweep` chain inside a seconds window (line 159). Byte-length pkt-line -> `gix-packetline` (rule 1): **resolved**. Same-second duplicate refnames: **not resolved** — deviation 5. Branch->tag fallback ambiguity -> gitrevisions order, `refs/` verbatim then `refs/tags/` then `refs/heads/` (lines 84-85): **resolved**. `peel` emits no `peeled:` on synthetic rows: **not resolved**, documented — peeling needs an R2 await inside a sync span (line 158). `symrefs`/`unborn` are the base writer's (write_ls_refs, spike-tested): **resolved**. KV ref replica must proxy `refs/at/`: **resolved** today — no replica exists (section 12); see Caveats for the sibling interaction.

## Crash walk-through
Killed inside the ls-refs span mid-`rows()`: read-only, nothing durable, client retries. Killed inside `commit_push` after `apply_one`'s reflog `INSERT`: the whole span rolls back — refs and reflog commit or vanish together (section 3; rollback on throw per platform-facts #4's model, the `PanicError` variant is scenario 15/day-1). Killed inside `ReflogExpire`: the `DELETE` and the re-`enqueue` are one sync span (lines 124-126), so under the span model they commit or roll back together; even split, the `DELETE` is idempotent and a missed enqueue only defers the next run. Nothing else is durable: no R2 keys, no pending state; push fallout remains the Janitor's (5.1-5.3). The real post-crash hole is cadence, not data: after `Done` deletes the row, the dedup bug means no next-day row exists, so expiry restarts only at write-back (d)'s `boot` re-enqueue — "once per DO cold start", not daily.

## Concurrency walk-through
Every reader and writer here is a sync span on one DO, so all interleavings are serializations. Two commits racing: `at_ms` runs inside each span, so `at` stays strictly increasing across both and reflog order equals commit order; `id DESC` is a redundant tiebreak (line 53). An ls-refs span racing a commit sees pre- or post-commit reflog, never torn — resolution is atomic with respect to ref moves, which is the whole point of putting it in the DO. `ReflogExpire`'s `DELETE` racing a `refs/at/` lookup: one wins outright; a just-expired row simply is not advertised, and a row that *was* advertised keeps its GC root only while it survives — a `want` for an expired-and-swept sha gets `ERR upload-pack: not our ref` and the client retries with a fresh ls-refs (needs >= `GC_QUIET` plus the sweep chain inside seconds; section 5). `GcMark` seeding while `ReflogExpire` runs: either order is safe — roots are a superset of resolvable rows, or smaller only by expired rows. The dedup bug's concurrency edge is that there is no interleaving where line 126 does anything: `enqueue` inside a slice can never insert while its own row is `running` (4.5).

## Interop check
`git fetch origin refs/at/1735689600/refs/heads/main` sends `ref-prefix refs/at/1735689600/refs/heads/main`; the emitted row name is `refs/at/` + spec verbatim (line 88), so it passes `write_ls_refs`'s prefix filter; git then sends `want <sha>`, served iff live — `gc_roots` covers it while its row exists. `git ls-remote origin 'refs/at/*'` sends `ref-prefix refs/at/` and gets <= 1,000 newest-first lines. `git fetch origin 'refs/at/*:refs/remotes/at/*'` produces `refs/remotes/at/<s>/refs/heads/main` — cosmetic, admitted. Same-second twin lines: `ls-remote` tolerates, wildcard fetch warns, and the name fetches the newer sha — wrong output for the earlier line (deviation 5). `ref-in-want` is not advertised, so no `want-ref` ever arrives; a client that sends one anyway gets `Error::Protocol` -> 400 with one `ERR` pkt-line (rule 7 mapping, correction 4). Byte lengths come from `gix-packetline` (rule 1); the first pass's UTF-16 bug class is gone. v0 clients see only real refs (`GET /_do/refs` has no `rows()` hook) and are refused on fetch anyway (rule 7). `peel` on a synthetic row emits no `peeled:` — documented; git treats a missing `peeled:` as absent annotation info. Scenario (a)'s "both moves with unique names" holds only if the two pushes land in different seconds — timing-dependent as written.

## Blockers
- `ReflogExpire` re-enqueues inside its own slice while its `jobs` row is `running`; `enqueue` dedup (4.5) refuses the insert, so the daily recurrence silently stops after the first run and retention becomes boot-driven. Return `SliceOutcome::Reschedule { run_at: now + DAY_MS }` instead — mechanical (deviation 2).
- Same-second collapse: `r.at / 1_000` (line 77) makes two moves of one ref inside one second advertise identical names with different shas, and the shared name re-resolves to the newer move — a wrong advertised name/sha pair on the wire. Emit `r.at` in ms (the namespace already parses 13-digit epochs) — mechanical (deviation 5).
- Four write-backs to foundation bodies (`ls_refs`, `apply_one`, GcMark, `boot`) are required for the feature to exist; A9's registry covers additions, not edits to section-1/3/5 code, so the contract must absorb them or the module cannot compile against it as written (deviation 3).

## Caveats
- `reflog_name_at` does not serve the enumeration query (deviation 7): every bare `refs/at/` listing is a full scan + sort; fine at 90-day scale, but a second index on `(at)` would serve it.
- ms-precision enumeration is silently empty (deviation 6); exact ms lookups work.
- Stale-advertisement residual: a `want` can fail `not our ref` if expiry plus the full GC chain complete between ls-refs and fetch; needs >= `GC_QUIET` inside a seconds window — documented, honest (line 159).
- If replicated-refs-edge lands, its `ls_refs_edge` answers a `refs/at/` prefix from the KV snapshot as a hit (its lines 116-127 render real refs only), silently emptying the namespace instead of falling through to `/_do/ls-refs` — one-line prefix guard needed there.
- `run_slice` is sync, not `async` (deviation 1); `pub(crate)` helper visibility is asserted, not declared as a write-back (deviation 4) — shared mechanical drift across siblings.
- Scenario (a)'s unique-names assertion is timing-dependent (deviation 5).
- `refs/at/<t>/HEAD` resolves to nothing (HEAD is `meta.head`, symbolic only, section 3) and bare short names resolve tag-first — git's own order, documented.

## Verdict
lands-with-caveats. The design is genuinely better than the first pass: both first-pass blockers are closed by the contract rather than by new code (no `ref-in-want` advertised, expiry on the shared dispatcher), and the log/ref atomicity the idea needs is section 3 step 4 verbatim. What remains are two one-line bugs with real consequences — a daily job that never recurs and enumeration names that collapse within a second into the wrong sha — plus four declared write-backs that exceed A9's literal scope. Fix those and this is a clean, cheap feature; none of it touches the push or fetch paths it rides on.
