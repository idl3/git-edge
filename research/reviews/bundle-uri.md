# Second-pass review: Bundle-URI support

# Review v2: bundle-uri (idea #12)

## Scores
- Feasibility 4/5 (v1: 4). Every host call is in `worker` 0.8.5: `create_multipart_upload(..).execute()`, `upload_part(u16, Data::Bytes)`, `complete`, `abort`, `resume_multipart_upload` (sync), `Bucket::{delete, get}`, `ObjectBody::stream`, `Response::from_stream`, `headers_mut`; `gix_hash::hasher(Sha1)` / `Hasher::{update, try_finalize}` exist in gix-hash 0.26 but were not run in the spike. Unverified and design-relevant: `MultipartUpload::upload_id()` (sweep's abort path needs it), BLOB `clone_plan.full` through `to_array::<Vec<u8>>` (same defect the precomputed-clone-pack review found: DO SQLite hands back an `ArrayBuffer`; use `raw()` + `Uint8Array::to_vec`), real R2 part-size enforcement (#6).
- Reliability 3/5 (v1: 3, different reasons). v1's two real bugs (live-refs header, leaked objects) are closed by shown code. New: the cut is one non-resumable slice that ignores 4.3, and a DO eviction inside it leaves the job row `running` forever, which dedup then turns into "no bundle for this repo, ever" (blocker 1); the header comes from a `clone.refs` row that the sibling proof does not write, and a stale plan (sibling blocker 1) produces a bundle that breaks the clone instead of degrading (blocker 2).
- Correctness 4/5 (v1: 3). Bundle v2 bytes, list reply, capability line and id rules are right; header and pack are provably one snapshot. One wrong git fact (delim) that the parser happens to absorb.
- Effort: weeks end to end. The module itself is days (~250 lines shown), but it cannot ship before precomputed-clone-pack's two fixes plus its `clone.refs` write-back, a dispatcher stale-`running` reset, and a resumable hasher.
Better than v1 with numbers: v1 had 3 blockers, all wire-visible (bundle rejected by git, unbounded R2 growth); v2 has 2, both state/lifecycle, and the pack it emits is byte-correct by 2.1.

## Contract compliance
Kept: modules `jobs/bundle_cut.rs`, `repo_do/bundle.rs`, `edge/bundles.rs` and dependency direction (1.1); `JobKind::BundleCut` as a `run_slice` arm, only `jobs::enqueue`, no `set_alarm` (4.1, 4.5); no `rows_written`, no CAS needed, `plan_cut`/`marked_rows`/`publish`/`bundle_uri` are `fn` and await-free; `gc_epoch` re-checked in every span that reads `objects` (3.2 shape); R2 deletion only of `dead` rows with `dead_at < now-GRACE` (5.3); foundation bucket never written (2.2), keys from `meta.repo_id` (8.2); `charge(1)` before every R2 call (7.1); client path bytes validated before use (10); section 12 read as "post-foundation module" with write-backs listed.
Deviations (each also in the structured list):
1. 4.3: "a slice checks the budget between units of work and returns `Continue` when either is 80% spent." `run_bundle_cut` never checks wall time and never returns `Continue`; the proof says so ("One slice, 512 MiB ... can exceed the 20 s wall guideline") and proposes a write-back instead of complying.
2. 5: sweep deletes `cutting` rows by `created_at < now-GRACE`; those were never "marked dead by a previous slice". Same shape as the `pending/` rule, but the wording is violated and the case where it matters (evicted cut) never reaches sweep (blocker 1).
3. 1.2/1.4 signatures: `read_range(key, off, len, &mut budget)` (4 args vs 3), `SliceBudget.req`, `bucket.repo` private field, `RepoDo::{bucket, meta_opt, meta_str, meta_i64}`, `store::random_hex32` — declared write-backs shared with siblings, not silent.
4. 1.1 rule 6 says the v2 advertisement is exactly five lines; a conditional `bundle-uri` line and `V2Command::BundleUri` are declared write-backs. 1.3 route table gains `/_do/bundle-uri`, declared.
5. 10: `Error::Conflict` for "gc ran during bundle cut" (Conflict is push state); `Error::Storage` for "entry past pack end", an index invariant (`Internal`). Minor.
6. `bundle_uri` is declared `fn` but calls `jobs::enqueue` -> `rearm` -> `Storage::set_alarm`, which is `async` in worker 0.8.5 (memo table). Foundation-wide inconsistency in 1.4, inherited, not this proof's.

## First-pass blockers
1. Header from live `refs`: **resolved in code, contingent**. `plan_cut` lines 85-96: `d.meta_opt("clone.refs")` feeds the header, bitmaps come from `clone_plan`, and "the live `refs` table is not read anywhere in the cut" is true of the shown code. Contingent because `clone.refs` does not exist: precomputed-clone-pack v2 `start()` stores `SELECT DISTINCT target FROM refs` (tips only) and `finish()` writes `clone.tips`, never names. Until that write-back lands the header cannot be built.
2. R2 objects never deleted: **resolved**. `publish` marks the old live row `dead, dead_at=now` and returns `Reschedule{now+GRACE+60s}`; `sweep` deletes `dead_at < now-GRACE` keys then rows (lines 111-125). Bounded at one live + one dead per repo, modulo blocker 1 here.
3. Hard dependency on a repack full pack: **resolved by reshaping**. The window loop plus `BundleWriter` assemble the pack from `clone_plan` bitmaps over any live packs; valid by 2.1 (full-object entries copy verbatim). Dependency moves to the clone plan, which is the right place.
Review-body items: newest-only listing (`LIMIT 1`, line 156) done; `refs/bundles/<name minus refs/>` wording fixed; multipart is the only write path; unknown `have`s are section 9 step 1.

## Crash walk-through
DO evicted after `read_range` #20 of a 300 MiB cut. Committed state: `bundles` row `cutting` with `upload_id`, `jobs` row `running` (marked in dispatch's span before the first await). Platform retries the alarm; `dispatch` selects `WHERE state='queued'` and finds nothing; `rearm` sets no alarm. Every later `bundle_uri` call hits `enqueue` dedup ("at most one queued or running row per kind") and is a no-op. Result: no sweep, no cut, the `cutting` row and its open multipart upload live forever, and the repo advertises an empty list until someone edits SQLite. The proof names this ("4.2 has no stale-`running` reset ... this proof does not add") and its slice is the longest in the system, so it is the job most likely to be evicted. Crash between `complete` and `publish`: `cutting` row with a finished object; swept after GRACE; correct. Crash between `plan_cut` and the `upload_id` UPDATE: an untracked multipart upload in R2 (R2 lifecycle aborts it; no key). Correct.

## Concurrency walk-through
Cut in flight, push commits main=b (own sync span at one of the cut's awaits): touches `refs`, `packs` (new row), `objects` (new pack); `marked_rows` reads only the plan's packs by `idx`; unaffected, bundle stays a valid snapshot, `bundles.refs_version < refs_version` so the next `bundle_uri` re-enqueues. GcSweep at an await: `gc_epoch` changes, next `marked_rows` returns `Conflict`, 4.4 retries in 60 s, `plan_cut` sees a dead plan pack and returns `None`, `Done`. No hole is read. Client downloading the old bundle while `publish` runs: key kept GRACE. All correct. The one bad interleaving is upstream: precomputed-clone-pack v2 blocker 1 publishes a plan whose bitmaps cover only a partial closure with the old tips; `plan_cut` cannot tell and cuts it. On the client, `unbundle_from_file` writes `refs/bundles/*` with `REF_SKIP_OID_VERIFICATION` (as I read bundle-uri.c), so the dangling tips are then sent as `have`, the DO ACKs them (they are live) and sends a pack that assumes their closure; the clone fails at connectivity ("did not send all necessary objects") with no fallback. "Nothing this module does can make a clone fail" is therefore not established; it needs a cheap self-check (e.g. every header oid's row is marked in its pack's bitmap) or an upstream fix.

## Interop check
- Capability: bare `bundle-uri` line; `server_supports_v2("bundle-uri", 1)` matches. Correct.
- Request: the proof says "no delim and no arguments". As I read `connect.c:get_remote_bundle_uri` (2.40+), git writes `command=bundle-uri\n`, capabilities, `0001`, `0000`. `parse_v2_command` sets `in_args` on `0001` and tolerates zero argument lines, so the arm parses either shape; nothing breaks, but the proof's git fact is wrong and scenario 17's trace should assert the `0001`.
- Reply: `bundle.version=1`, `bundle.mode=all`, `bundle.heuristic=creationToken`, `bundle.<32hex>.uri=<absolute>`, `bundle.<32hex>.creationToken=<ms>`, `0000`. Matches `bundle_uri_parse_line`; ids dot-free; absolute URI so `baseURI` resolution is moot. Correct.
- Bundle file: `# v2 git bundle\n`, `<oid> <refname>\n`..., `\n`, `PACK` v2 header with plan popcount, full-object entries, SHA-1 over pack bytes only. Matches gitformat-bundle; `unbundle` -> `index-pack --fix-thin --stdin` accepts. Correct.
- Versions: the protocol `bundle-uri` command client is 2.40+; 2.38/2.39 only have `--bundle-uri=<url>`, so the "older clients download every listed bundle" concern is moot. CI matrix 2.43-2.47 all fine.
- Auth on the private URL: `git remote-https get` handles 401 via the credential helper; second prompt without a helper, as the proof states.
No breaking wire byte found on any path.

## Blockers
1. Non-resumable slice + stuck `running` (4.3 violation, walk-through above): one eviction mid-cut disables bundles for that repo permanently. Fix: dispatcher resets `running` rows older than N minutes to `queued` (foundation, ~3 lines), and either cap a cut at what fits 20 s (~64 MiB) or carry SHA-1 state (`[u32;5]` + length) in the cursor with 8 MiB parts and `Continue`, which also fixes `GcConsolidate`.
2. Header source and correctness are borrowed: `clone.refs` is an unwritten write-back to precomputed-clone-pack, and that proof's stale-plan bug turns a bundle into a clone-breaking artifact rather than a fallback. Fix: land the sibling's two fixes and the `clone.refs` capture in `start()`; add a header-oid-marked check in `plan_cut`.

## Caveats
- 512 MiB gate sums `packs.bytes`, not marked bytes; repos with big dead-but-live history get no bundle until GC consolidates.
- Demand enqueue while the job waits GRACE+1 min for its sweep is a dedup no-op; a fresh plan can wait ~1 h. Every clone of a pushed-since repo enqueues a job that does only a sweep.
- Public mode is deployment-wide; unauthenticated-but-unguessable URLs for every repo. Private mode is uncached R2 on every clone.
- Unverified per memo: `upload_id()`, `http_metadata` on the multipart builder, `Hasher::try_finalize`, BLOB via `to_array` (likely needs `raw()`), `Response::from_stream` at runtime, real R2 part rules (#6), deployed subrequest limit (#7), `clone.c` skipping bundles under `--depth`/`--filter` (read, not run).
- `serde_json` and `web_sys::Crypto` are outside the memo manifest; trivial adds.
- Opt-in only (`transfer.bundleURI=true`), so the DO-bypass benefit reaches almost no default client; the shared value is the same bitmaps precomputed-clone-pack already serves in band.

## Verdict
risky. Wire and file formats are right, the pack is correct by construction, and all three first-pass blockers are closed by code that is actually shown. But the shown job violates 4.3 and, on the first eviction, silently and permanently stops working for that repo, and the header it emits depends on a row the sibling proof does not write and on that sibling's own open blocker. With the dispatcher reset, a resumable cut, and the sibling write-backs this is lands-with-caveats in days of module work; without them it is a feature that works until it does not.
